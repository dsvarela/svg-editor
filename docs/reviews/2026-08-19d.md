# 2026-08-19d: the 127 survivors in `ops.ts`, read

Range: no commits. This one covers a measurement rather than a diff. The
mutation sweep of 2026-08-19c left `src/model/ops.ts` at 127 survivors of 360
sites and stopped there, and a survivor count is not a finding until somebody
has read the survivors. This is that reading, and what it changed.

## What the 127 reduce to

Four classes, all four already in the register, and three of them named in
earlier reviews here.

| Class | Where | Survivors |
|---|---|---|
| A fixture at the origin, so a difference and a sum are the same number | every fixture in `ops.test.ts` is spelled `M0 0 …` | most of them |
| A refusal no test reaches, beside a happy path that is covered | `deleteNode`'s index bound and its open-path endpoint branch, `latentHandle`'s two guards, `filletAt`'s twelve | about 30 |
| A margin nothing exercises | `nearestOnPath`'s bounding-box reject | 11 of that function's 12 |
| A run of `||` where only one alternative is ever true | `deleteNode`, `latentHandle`, `nearestOnPath` | throughout |

The origin class is the one worth stating plainly. `latentHandle` returns
`a + (b - a) / 3`. With `a` at the origin that is the same number as
`a + (b + a) / 3`, and every path in `ops.test.ts` starts at `M0 0`, so no test
in the file could tell the correct expression from the wrong one. The same held
for `deleteNode`'s handle rescale and for `cornerAt`'s two rays.

## What was fixed, and how

**The origin class was not fixed by moving the fixtures.** Sixty edited
fixtures leave the next person free to write the sixty-first at the origin.
What replaced them is the property those fixtures were failing to state:
[`test/equivariance.test.ts`](../../test/equivariance.test.ts) runs eighteen
operations twice, once on a path and once on the same path moved by
`[137, -61]`, and requires the two to agree. Any term that confuses a point with
a vector breaks that agreement, the offset is supplied by the file rather than
by whoever writes the next test, and an operation added to the table inherits
the check.

It does not reach an error between two quantities that are both already
differences: translating moves both by the same amount, so a sign flip between
them survives. That is written at the head of the file.

The file also carries a check on itself. `sameGeometry` compares a translated
copy against a translated original, so a mistake it cannot see is a mistake the
whole file cannot see; one test therefore builds the known-wrong expression by
hand and requires the harness to reject it.

**The margin was fixed by stating the reject's contract instead of sampling
it.** `nearestOnPath`'s box test exists only to be faster. Its whole obligation
is that the answer is the same as projecting onto every segment and taking the
smallest, and that is checkable by sweeping points rather than by guessing where
the band is. [`test/nearest.test.ts`](../../test/nearest.test.ts) sweeps a grid
of 693 points across four overlapping shapes at four values of `maxDist`,
and against a filter, comparing each answer with an exhaustive search.

Of six mutations tried on the reject and on the bound it reads, four go red:
either margin subtracted instead of added, on either axis, and the bound halved.
The two that do not are provable equivalents. `>` to `>=` tests a boundary a
point could not have won from, since its distance would equal the bound and the
comparison below is strict. `||` to `&&` makes the reject reject less, and a
weaker optimisation cannot change an answer; a test that killed it would be
asserting that the optimisation fires rather than that it is correct.

**Three pieces of `ops.ts` were rewritten so the survivors had nowhere to
live**, rather than tested where they stood:

- `latentHandle` chose its neighbour with two parallel ternaries on the same
  discriminant, one of them a `sp.closed || …` disjunction. It now takes one
  step of `+1` or `-1` and asks whether that step leaves the array. The
  disjunction is gone and with it the survivors on it.
- `deleteNode`'s `segmentIsLine(sp, i < n ? i : 0)` had a dead ternary: the
  function has already returned for `i >= n`, and for the last node of an open
  path, so `i < n` is always true. Deleted.
- `deleteNode` wrote the handle-rescale arithmetic out twice. It is one
  `stretchHandle` now, which halves the sites that arithmetic offers.
- `nearestOnPath` stated `best?.d ?? maxDist` twice, once as the box margin and
  once as the distance a segment must beat. The box test and the win test are
  the same predicate at two resolutions, and two statements of it are a way for
  them to disagree. One `reach`, read once.

**Four guards got tests**, because a boolean return is the contract and cannot
be defined out of existence: `deleteNode` refusing an index the subpath does not
have and changing nothing while it refuses; `deleteNode` clearing the handle
that faces the removed end, at either end; `latentHandle` on a two-node subpath,
which is the smallest one that has a segment and is what a ring of three becomes
when it loses a node.

Every one of these was watched failing before it was believed. The mutations
used are listed in the commit.

## One finding outside the range

`tools/mutate.mjs` was still running from the previous session and had
`src/model/ops.ts` mutated in place. Two edits were made to that file before the
sweep was noticed, and the sweep reverted both. Nothing was lost, because the
edits were re-applied and the sweep's own recovery record was cleared, but the
constraint in `CLAUDE.md` is stated for `npm run drive` and for a hand edit and
says nothing about a sweep left running across a session boundary. It says so
now.

## The 89 read, and the count taken apart

The rewrites above put `ops.ts` at 89 survivors of 355. All 89 were read, and
each of the 18 arithmetic sign flips among them was applied against the whole
1 236-test suite rather than the eleven scoped files. **All 18 survived that
too**, so the scoping was not why they lived.

Split by what a survivor is, the count is mostly not findings:

| | Count | What it is |
|---|---|---|
| Cannot be killed | about 38 | A strictness flip on a floating-point tolerance: `< 1e-12` to `<= 1e-12`, `<= MEET`, `< SAME_PLACE`. Behaviour differs only when a value lands exactly on the threshold. No test can reach that, and none should try. |
| Provably equivalent | about 12 | Real branches that cannot change an answer. `nearestOnPath`'s reject weakened by `\|\| → &&` still finds the true nearest, slower. `distributeNodes`' `items.length + 1` moves the last item to where it already is, and `SAME_PLACE` then returns early. |
| Genuine gaps | about 39 | Something the tests should have said and did not. |

**Roughly 55% of the number was never a finding.** That is what the figure is
worth on this file, and it is the reason to read survivors rather than track a
count.

## Nine gaps that reach a caller

Each of these has a live call site that reads the answer, so a wrong answer
would be a wrong editor rather than a wrong internal number. **None of them was
a live defect: the code was correct in all nine cases**, and what was missing
was any test that said so.

| Function | What a wrong answer would do |
|---|---|
| `splitSegment` | Returns the index the controller selects next, so off by one picks the node next door |
| `setSegmentCurved` | Handles outside the span, so a line converted to a curve draws as a loop |
| `fuseNodes` | Handles moving opposite to their node, destroying the curvature either side |
| `mergeEnds` | `slice(0, -1)` as `slice(0, +1)` keeps one node of the first path and drops the rest |
| `fuseDegenerate` | A gap measured as a sum of coordinates fuses nothing at all away from the origin |
| `sharedCornerRadius` | The wrong neighbour, so the largest-radius clamp in the rail is wrong |
| `cornerArcReach` and `cornerRadiusAtReach` | One relation spelled twice; if they stop inverting, the corner control slides out from under the pointer |
| `filletAt` | A wrong corner angle, so a rounded corner stops being recognised as one |
| `closeSubpath` | Refusing to close a two-node subpath, which is what a ring of three becomes when it loses a node |

[`test/answers.test.ts`](../../test/answers.test.ts) holds them. It covers what
`equivariance.test.ts` states it cannot reach: two quantities that are both
already differences, where a sign flip between them commutes with translation.

**Four of the nine first survived those new tests, because the new fixtures were
axis-aligned.** The class this whole wave is about, reproduced inside the fix
for it: `M10 20 L70 20` has a zero step in y, so adding it and subtracting it
agree. The fixtures are diagonal now.

`deleteNode`'s `wasLine` carried a third conjunct, `prev.hOut === null`, that
`segmentIsLine` already implies. Deleting the entire branch it guards leaves
1 251 tests green, because a straight pair has no handles for the general path
to rescale, so it reaches the same splice. It is a fast path and not a second
behaviour. The conjunct is gone; the branch is kept and named as the
optimisation it is, since it saves two `cubicLength` walks per node and a
marquee delete over a traced drawing pays that thousands of times.

## Three closed by decision, not by code

Written down so the next audit does not re-find them as bugs.

- **`deleteNodesSplitting`'s `let first = -1`.** Mutating the sentinel to `+1`
  changes behaviour only when `remove` is non-empty and holds no index the
  subpath has. Every caller builds `remove` from resolved node indices, so it is
  defensive against a state no caller can produce.
- **`filletAt`'s `alpha > Math.PI - 1e-6`.** `alpha` is an `acos`, so it never
  exceeds pi and the mutated `Math.PI + 1e-6` is a condition that can never be
  true. Reaching the difference needs a construct the tangency check on the line
  below rejects anyway.
- **`distributeNodes`' `items.length - 1`.** Proved equivalent above.

## Where the sweeping stops, and why

**`ops.ts` is done, and this is the last mutation sweep of this wave.** The rule
that says so: stop when the survivors stop being reachable. What is left in this
file is tolerance strictness, sentinels behind callers that cannot reach them,
and equivalents proved here. There is no tenth defect in it.

The yield says the same thing. The 2026-08-19b audit returned 5 findings that
changed or destroyed somebody's work; the fix review after it returned 1; this
wave, across four sweeps, returned **none**. What it returned instead is nine
pieces of correct code that nothing was pinning, which is worth having and is
not worth another sweep.

## What this did not do

It deliberately did not sweep `src/main.ts`, `src/tools/` or `src/view/`.
Mutation testing measures what unit tests notice, and those surfaces have almost
none, so a sweep there returns survivors that mean only that. They are a lane
for a reading review, not for this instrument. It did not extend the equivariance table beyond
`ops.ts`, though `parse.ts`, `serialise.ts` and `svg.ts` all showed the origin
class in the same wave. It left `filletAt`'s twelve refusals covered by the
tests written in 2026-08-19c rather than by anything new. And it did not lower
the tool's noise floor: teaching `mutate.mjs` to skip a strictness flip against
a float tolerance would drop this file from 89 to about 51 and make a future
count mean something without a reader discounting it by hand. That is filed
here and nowhere else.
