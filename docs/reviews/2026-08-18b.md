# Review, 2026-08-18b

Covers `633ec47`, the commit that closed the comment and reachability backlog.
It was the only commit in the repository with no review, and it was written by
whoever wrote the checkers that pronounced it clean, so its green run was not
independent evidence of anything.

**What it found: 1 defect the commit itself introduced, 6 more of the same class
already in the tree, 1 duplication the same pass walked past, 4 measurements
deleted from comments that needed them, and 1 false claim in the commit
message.** The defect and its six siblings are one finding: a comment can come
away from the declaration it documents, and nothing here could see it.

---

## A comment can lose its code, and no check could tell

Moving `nodeIdAt` from `src/model/doc.ts` to `test/helpers.ts` took the function
and left its documentation:

```ts
/**
 * The id of the node at a position, for the callers that have a position and
 * need an identity: a hit test, a freshly split segment, a test fixture.
 */
/** The same, when only the positions are wanted. */
export const selectedRefs = ...
```

Two doc blocks with no code between them. An editor renders the last `/**`
before a declaration and nothing above it, so the first block is text no reader
will be shown, and `selectedRefs` reads as "the same" as a function that is not
in the file.

**The commit had already named this class and fixed one instance of it.** Its
message describes exactly this shape in `src/model/knots.ts`, where
`removeRedundantNodes`'s doc had drifted two functions above its declaration.
One instance was moved back. Nothing looked for the others.

There were six more, and one of them was the one the commit had just made:

| Site | What had come away |
|---|---|
| `src/model/doc.ts` | `nodeIdAt`'s doc, function gone (made here) |
| `src/model/ops.ts` | `roundCorner`'s doc, above `interface Corner`, 53 lines from `roundCorner` |
| `src/model/store.ts` | `checkpoint`'s first block, invisible in every tooltip of it |
| `test/controller.test.ts` | a note about both curve fixtures, rendered on the first |
| `tools/drive.mjs` | `settle`'s doc, above `describedBy` |
| `tools/drive.mjs` | a paragraph about the scenario try/catch, above `check` |

**`comments/check.mjs` reported zero on this tree throughout.** It could not have
done otherwise: `commentBlocks` groups consecutive comment lines, so a detached
doc and the doc below it arrive as one block, and every check reads them as one
comment. A short orphan is invisible; a long one is reported as a comment that
should be shortened, which is the wrong instruction. That is what made this class
survive four reviews.

**The fix is the check**, `orphan`, added to the handbook rather than to this
repository. It is an error when the second block is a doc comment, since the
earlier text can never be rendered, and a warning when both are plain, since two
paragraphs above one statement lose nothing. On this tree the split was 7 errors,
all real, against 3 warnings of which 1 was: `tools/drive.mjs` had a general
statement about what makes a scenario a check sitting above an unrelated helper,
saying what `check`'s own doc and `--audit` both already say.

Four cases in the handbook's `test.mjs` hold it, and each was watched failing
with the check disabled.

## The duplication pass found one pair and missed another

The commit's real find was that `applyTransform` wrote `[-1,0,0,1,0,0]` and
`[1,0,0,-1,0,0]` inline while `core/affine.ts` exported `flipX` and `flipY`
returning exactly those. Both are called now.

In the same file, unchanged:

```ts
const tol = Math.max(invisibleAt(st.decimals), 0.01);   // offsetSelection
const tol = Math.max(invisibleAt(st.decimals), 0.01);   // strokeToPathSelection
```

One rule about how closely a fitted outline follows its source, written twice and
named nowhere. It is `outlineTolerance` now, with the thing that makes it not the
knot-removal tolerance written down beside it, because the two look identical and
are not.

## The commit message states a reason that is not true

It records `removeInvisibleNodes` as deleted because it was "subtly not what
production wants -- the three real sites floor the tolerance at 0.01 and it did
not", and says "its two tests now exercise the composition that ships".

The wrapper was `removeRedundantNodes(sp, invisibleAt(decimals))`. The only site
in the editor that removes knots, `Commands.simplifySelection`, computes
`invisibleAt(decimals)` with no floor and argues in its own comment for exactly
that: a node whose removal cannot change a character of the saved file has moved
nothing observable. The wrapper matched it. The two sites that floor at 0.01 are
offset and stroke-to-path, which fit outlines rather than remove knots.

**Deleting it was still right**, on the reachability ground the pass was run for:
nothing called it. But the tests that were rewired exercise the composition they
always did, spelled out, and no coverage changed. A wrong reason in a commit
message is what the next person reads when they wonder whether to bring something
back, which is why it is corrected here rather than left.

## What the pass got right

The mechanical work held up. Seven un-exports and four deletions, all confirmed
by `tsc`. The flip helpers correctly wired. The NUL byte in `src/model/snapping.ts`
correctly diagnosed as the reason five names read as dead, and `#guides` verified
unforgeable rather than assumed: `makeShape` takes every shape id from `nextId`
as `prefix-n`, and an imported `id` attribute becomes the shape's name at
`src/io/svg.ts:263` and `:292`.

What it got wrong is what a shortening pass is most likely to get wrong. It cut
qualifiers to reach a length, and it fixed instances of a class it had itself
just named.
