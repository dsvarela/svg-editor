# Review, 2026-08-12

Five adversarial lanes over everything written since
[the last review](2026-08-11.md): the backdrop's move into the history,
Simplify, the transform box, the document canvas, Style with the tabbed
inspector, and corner rounding. Roughly 4 200 lines.

Lanes: geometry and numerics, state and history, UI and DOM, documentation
against code, and tests against the code they claim to cover. Each returned
findings with a concrete reproduction; every finding acted on below was
reproduced here first, and the four biggest were reproduced by running them.

**61 findings raised, 9 defect classes fixed in code, 17 documentation claims
corrected, 6 tests rewritten because they could not fail.** Three findings were
closed as guesses that did not survive checking, and four are recorded as
deferred with a reason.

---

## Class 1. A press that never became a drag destroyed the redo stack

**Severity: high. Every click on the canvas.**

Every drag branch called `store.checkpoint()` on pointerdown, before it could
know whether the gesture would change anything, and `checkpoint` clears the redo
stack. So: edit, undo, click a node once without moving, and the redo was gone
along with an empty entry left on the undo stack.

This is exactly the failure §16 says `tryEdit` exists to prevent. The fix was
applied to buttons a month ago and never to drags.

Measured before the fix:

```
canRedo after a bare checkpoint: false
canUndo after a bare checkpoint: true
```

**Fixed** by making the checkpoint lazy: drag starts open a batch and nothing
else, and the mutating cases in `onMove` became `store.edit`, which checkpoints
once per batch. The snapshot therefore lands on the first real change, which is
the state before it. `pan` deliberately stayed an `update`: the camera is not
the document.

**This exposed a second defect in the same breath.** `abortDrag` decided whether
to roll back from `batchOpen`, which asks "did we open a batch", not "do we have
an entry of our own". A press that never moved now has the first and not the
second, so Escape would have popped somebody else's edit. `Store.batchDirty`
answers the real question.

## Class 2. An open number-field batch swallowed the next drag

**Severity: high.**

`streamed` and `liveNum` open a history batch on the first `input` and close it
on `change` or `blur`. A number field fires `change` only on blur, and
`pointerdown` is delivered *before* mousedown moves focus. So pressing on the
canvas while a field still had focus ran the whole drag inside the field's batch.

Measured before the fix, typing 120 into the canvas width and then dragging a
shape and pressing Escape:

```
drag checkpoint taken? false
viewBox width after Escape: 100  (was 120)
canRedo after Escape: false
```

Escape rolled back the *field's* edit, and offered no redo.

**Fixed** with one capture-phase `pointerdown` listener on the window that closes
every open stream. A press anywhere else now ends the field's entry first.

## Class 3. Nothing caught a gesture whose end never arrived

**Severity: high, low probability.**

`pointerup` was bound on the overlay only. `setPointerCapture` is already in a
try/catch that concedes it can fail, and a release outside the canvas or a button
let go while the window is unfocused then never reaches `onUp`. The batch stays
open, `checkpoint` returns early **for the rest of the session**, and no undo
point is ever recorded again with nothing on screen to say so.

**Fixed** with `window` fallbacks for `pointerup` and `blur`, and by wrapping
`onUp`'s body in `try/finally`. Everything above the old `closeBatch()` call runs
listeners: the marquee's `update` notifies every subscriber, which touches forty
DOM nodes and re-serialises the document. The ending of a gesture is not allowed
to depend on the rest of the application behaving.

The toolbar's Undo and Redo also bypassed the mid-drag guard the keyboard has had
since §16; a second finger on a touchscreen reaches them. `Controller.busy` now
gates both.

## Class 4. Ctrl+arrow bending had been dead code for a month

**Severity: medium. A documented feature that could not fire.**

Two lanes found this independently. `if (mod) return` sits before the key switch,
so the `if (mod)` branch inside the arrow case is unreachable. The guard was
itself a fix from the last review, for `Ctrl+E` also selecting the ellipse tool;
it took the bend keys with it, and the reference manual, the how-to and the
in-app note all still promised them.

**Fixed**: the guard now lets the arrows through, since `Ctrl` gives them a
second meaning of their own rather than belonging to something else.

Related, from the UI lane: the window keydown handler skipped `INPUT`,
`TEXTAREA` and `SELECT` but not `BUTTON` or `UL`, so arrowing through the shape
list or the new tab strip **also nudged the drawing** one grid step per press,
with an undo entry each. Fixed by bailing on `e.defaultPrevented`.

## Class 5. What you saw was not what you exported

**Severity: medium, and newly visible.**

`renderArtwork` multiplied each shape's stroke width by the zoom, pinning every
stroke to a constant number of screen pixels. §17's rule is that overlay chrome
holds its screen size *and the drawing scales*; the artwork is the drawing.

Tolerable while every shape was a one-unit hairline and nothing could change the
width. The Style panel made it a real defect the same day it shipped: two shapes
set to widths 1 and 4 rendered identically. **Fixed**: the artwork draws its true
width.

## Class 6. Rounding a corner could leave two anchors on the same point

**Severity: medium.**

Two routes: the clamp, where `cut` reaches the full side length and the tangent
point lands on its neighbour; and two fillets meeting in the middle of a side
they share. Both produced a zero-length command in the exported path, and a path
carrying one **can never be simplified again** — a zero chord leaves the fitter
with no tangent.

**A test of mine asserted the bad outcome.** `test/ops.test.ts` checked
`nodes[2].pt` was `[40, 0]` while `nodes[1]` was also `[40, 0]`. That is how a
defect acquires a test written around it.

**Fixed** by reusing the neighbour where a fillet lands on it, which is also
right geometrically: two arcs that meet share the point where they meet. A 40 by
20 rectangle rounded at 10 is now a proper six-node stadium.

## Class 7. Simplify's reported error was not a bound

**Severity: medium.**

Three things move the outline and the reported number only covered one. The fit
is measured against the sampled polyline, which is itself up to
`tol * SAMPLE_RATIO` from the true curve; straightening a nearly-flat result
moves it again. On one blob at a tolerance of 8 the outline actually moved 8.33
while the status line said 7.85.

Worse, `fitCurve`'s recursion cap **is** reachable — the comment claiming
otherwise was wrong, and a stroke of nine hundred samples with twenty
oscillations reaches it. When it fires, the last fit was applied regardless of
whether it met the tolerance.

**Fixed** by treating the tolerance as a budget split between all three sources,
handing the fitter what is left, and refusing outright when even that cannot be
met. There is now a test that measures the real deviation against the reported
number on that blob.

## Class 8. Three numerical defects in the fitter and the transform maths

- **Newton's method was not clamped to [0, 1].** `cubicAt` extrapolates happily
  outside it, so an escaped parameter let `maxError` measure the distance to a
  point that is not on the returned curve: a fit that missed by 18 units reported
  an error of 1e-12. Fixed by clamping the step.
- **The Wu and Barsky guard had no upper bound**, and when a run closes a loop
  the chord is zero, so the lower bound is zero too. A control point ended up
  1 075 units from a 93-unit span. Fixed with a ceiling.
- **`atan2(0, 0)` is zero, not undefined**, so sweeping the rotate pointer
  through the centre of the selection applied minus the grab angle in one jump.
  Fixed, with a test.

Also: the half turn reported `-180` for a drag that went the other way, and
`FLAT` (a length) was compared against a squared length, which silently ignored
Shift on a very small selection.

## Class 9. Six controls, one panel, and a sweep that took too much

- The new **Round** control stayed keyboard-reachable while its group was greyed
  out; `pointer-events: none` stops the mouse and not Tab. Every older control in
  that group was disabled explicitly and the new ones were missed.
- The sticky tab strip painted over the sticky group headers, so `SHAPES` and
  `STYLE` slid underneath it instead of pinning below.
- `.row .seg button` overrode the padding of `.seg.spread button` but not its
  height, collapsing the fill-rule buttons to 17px next to 26px fields.
- `.group` and `.tabs` were hard-coded to 288px inside a 288px column that also
  holds a border and, once it scrolls, a scrollbar.
- `#f00` was treated as an exotic colour the picker could not show, and unticking
  `none` then replaced it with whatever the swatch happened to hold.
- `<label for>` pointed at a `<div>`; `.chk` had no stylesheet rule at all.
- **`pruneDegenerate` swept the whole document with no checkpoint.** Finishing a
  pen path deleted any one-node subpath that had arrived by import, and the only
  undo that brought it back also undid the drawing. Now scoped to the shape the
  pen was drawing, which is the rule `deleteSelection` already followed.

## Tests that could not fail

The test lane broke the source and re-ran, rather than reasoning. Eight of its
findings were confirmed that way. Six tests were rewritten:

| Test | Why it could not fail |
|---|---|
| `holds the bytes for as long as any entry can reach them` | Stopped before `reap` ever looked at anything; deleting the reachability guard passed the whole suite |
| `leaves the marquee alone while locked` | Asserted only that the image had not moved, which is also true if the backdrop swallows every drag |
| the whole backdrop block | Never set `visible: false`, so removing that guard passed |
| `reports the short way round` | The fixture's raw angle never left the range the normalisation exists to fix |
| `keeps the aspect ratio when asked` | Rejected one wrong rule; min-of-the-two is also equal and also wrong |
| `is one undo step` (fit canvas) | Never asserted `canUndo === false`, so a second checkpoint went unnoticed |

Two more were noted and left: the transform handle tests feed `handlePoint` back
into `scaleMatrix`, so their expected values are the implementation's own output.
They are tautologies, but `anchorPoint`'s literal assertions cover the same
ground, so the gap is smaller than it looks.

## Documentation

Seventeen claims corrected. The pattern is the same as last time: **statements
that were true when written and were quietly falsified by a later change.** The
README said 324 tests and 10 files; the shopping list still said Simplify did not
exist and quoted a 153 kB bundle; the manual promised `Ctrl`+arrow bending that
could not fire, said Align needs three nodes when it needs two, listed the
serialiser's output without `Q`, described the Theme button as cycling three
states when it inverts two, and put the grid readout in the wrong place.
ARCHITECTURE printed sections 16 and 17 after 23, and its circularise worked
example quoted angles that were not the ones in the test it cited.

## Closed without change

- **Rotor zones covering a neighbouring shape's nodes.** Raised as a guess and
  not measured. It is the trade every editor makes, and the alternative is a
  rotation zone nobody can find.
- **`roundCorner` throwing on an out-of-range index.** No reachable path; guarded
  anyway, since the neighbouring functions all skip defensively.
- **`penDown`'s bail-out desynchronising the batch depth.** The desynchronisation
  was real and is fixed, but the branch was not shown to be reachable.
- **A latent temporal dead zone at `swatchOf`.** Not an error today; one line of
  "refresh the list at boot" would make it the failure that has already bitten
  twice.

## Deferred

- **`keepAspect` on a node selection** scales an axis the box has no extent in,
  because the box is the bbox of the anchors only. Defensible as "Shift means
  uniform", but the user has no on-screen height to have asked for it.
- **`aria-label` overriding visible labels** on paired coordinate fields. Real
  WCAG 2.5.3 issue, cosmetic in practice, mechanical to fix across the panel.
- **The `simplify` scenario cannot prove the tolerance is derived** from the
  document, because it never resizes it. A hardcoded constant would pass.
- **The `backdrop` scenario's `after > before`** passes for any positive
  movement, where the grid makes the answer exactly 10.
