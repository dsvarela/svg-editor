## The cache did not notice an out-handle moving

**`src/view/pathcache.ts:79`. `matches` returns "still the same" when a node's
`hOut` has moved**, and no test disagreed. The row that reads the out-handle's
coordinates can be inverted and the suite stays green.

What it costs: drag an out-handle and the outline does not follow it. The
overlay draws handles from the model and the artwork draws from the cache, so
the handle moves under the pointer and the curve it governs stays where it was
until something else invalidates the entry.

Why nothing caught it: `test/pathcache.test.ts:57` moves an `hIn`, and `:58`
makes an `hOut` **appear**. Appearing is caught one line earlier, by the
presence flags at `pathcache.ts:71`, which encode `hIn` and `hOut` as a number
without their positions. So the file has a moved-handle case and a
handle-that-arrives case and no moved-**out**-handle case.

**This is the half-a-pair class the register already carries.** `flipX` had a
test and `flipY` had none, and returning the identity from `flipY` passed all
1 110 tests; `mul`'s first cross term had no fixture that composed two turns.
Each time the tested half made the pair look covered, and each time the name of
the covered case is what did it: "a handle moves" reads as both handles.

## The instrument took a flag it should have refused, and offered sites it should not

Two changes to `tools/mutate.mjs`, both found by using it.

**An unknown flag was silently dropped.** `--list` is not a flag; listing is
`--limit 0`. The argument parser filtered out anything starting with `--` and
kept going, so the target stayed a target and a typo ran a full destructive
sweep. It did that here, on a tree that had a browser sweep running on it, and
the browser sweep then failed `transform`, `smartGuides` and `referencePoint`.
`src/model/ops.ts` was being rewritten and restored under it for the whole of
that time, and the mutation live when the sweep was killed was `latentHandle`
returning a difference as a sum. Which mutation each scenario met is not
recorded and does not matter: **that red said nothing about the code**, the
sixth time a signal in this project has been worth nothing. `tools/contrast.mjs`
already refuses an unknown flag and says why in its own comment; the one tool
that rewrites the source did not.

**A boundary against a float tolerance can never be a finding, and was being
offered as one.** `<` against `<=` where the bound is an epsilon, and
`+ 1e-12` against `- 1e-12`, differ only on inputs no fixture can produce.
`2026-08-19d` estimated 38 of `ops.ts`'s 89 survivors were this and discounted
them by hand. The tool skips them now, on the argument that already skips a
comment and the `<` of a type argument: `src` goes from 3 930 sites to 3 767.

The first version of that skip read the token beside the operator and was wrong
about where the epsilon usually is. **The bound is the epsilon added to
something**, `m <= 1 + 1e-12`, not the epsilon itself, and it turns up as often
inside an argument: `Math.floor(Math.log10(x) + 1e-12)`. All four of
`src/view/viewport.ts`'s tolerance lines are one of those two shapes, so the
first version skipped none of them, and the file came back 31 survivors of 42.

A boundary reads its whole operand now, out to the nearest `&&`, `?`, `,` or
unbalanced bracket, and an additive operator reads the token beside it.
viewport falls from 42 sites to 33, **and every one of the 9 removed was a
survivor**: all six on line 98 and one each on 96, 135 and 163. The two real
boundary survivors, `x > 1` and `snapStep > 0`, are untouched and still on the
list, along with the five on `fitBox`'s margin arithmetic, which no test
reaches.

## The slide margin is one fact in three places

## The Slide field shows a number the document does not hold

Type `0` into **along %**. `slideActiveTo` clamps to `0.1` and stores
`t = 0.001`; `refreshSlide` writes back `Math.round(0.001 * 100)`, which is `0`.
The field then reads `0` for a node that is at a tenth of a per cent, and the
same happens at the other end: `100` is stored as `0.999` and displayed as
`100`.

The field's own `min="0"` and `max="100"` invite exactly those two values, so
this is not a corner somebody has to hunt for. Verified by arithmetic rather
than argued: `Math.min(99.9, Math.max(0.1, 0)) / 100` is `0.001`, and
`Math.round(0.1)` is `0`.

It is the second-priority class, what the user sees diverging from what is
stored, and it is the mild end of it: nothing is lost, and the disagreement is
a tenth of a per cent.

## What the guards do agree about

Checked because a mismatch here would be an empty history entry, and it is not
one. `slidingParent` answers through `nodeRemovalCost`, which refuses a subpath
with fewer than two segments and both ends of an open path;
`slideNodeTo` refuses the same two and adds `0 < t < 1`. The second is strictly
narrower, so nothing can start a slide the model then declines.

The batch is safe for the same reason and for one more: `Store.beginBatch` and
`endBatch` are a counter, and no history entry exists until an edit takes a
checkpoint. An Alt-press released without a move leaves nothing behind.

The ghost is cleared correctly. `onUp`'s `finally` sets the drag to `none` and
calls `schedule()`, and `render` reads `slidePath` from the drag, so the dotted
curve cannot outlive the gesture.

## Closed by decision

- **`pathcache.ts:66`, the subpath-count check, survives.** Line 64 compares
  `sig.length` against `sigLength`, which is `1 + 2S + 7T`. Two documents with
  different subpath counts and equal signature lengths need `2(S1 - S2) =
  7(T2 - T1)`, and every solution I could construct is contradicted by the
  per-subpath loop below it. Recorded as a redundant guard rather than as a
  gap, because no distinguishing document exists that I could build.
- **`slidingParent` and `slideNodeTo` state the same refusals twice.** Kept:
  `slideNodeTo` is exported and a caller may hold a parent from an earlier
  frame, so its guards are about its own arguments rather than a copy of the
  other function's.
