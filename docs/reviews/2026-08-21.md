## Three functions in `bezier.ts` had no test at all

`src/core/bezier.ts` is imported by eighteen test files, which is more than any
other module here, and that is exactly what made the gap invisible: everything
uses it and nothing checks it.

**`cubicBBox` is the one that matters.** `src/model/doc.ts` builds every shape's
box from it, and that box is the selection rectangle, **Fit**, **Align** and the
exported `viewBox`. The block that handles a derivative root falling strictly
inside the parameter range survived six ways, including `axis === 0` inverted,
which sends an interior x-extremum into the y bounds. **No test measured the box
of a shape whose curve leaves its endpoint range**, so a bulging curve could be
boxed as if it were flat and nothing would say so.

Five tests now: three bulges in different directions, one straight run, and one
property sweep of 200 samples requiring every sample inside the box **and**
something touching each of the four sides. The tightness half is what catches
the interior-root guard: widen `t <= 0 || t >= 1` to `&&` and the box grows past
the curve, which containment alone would accept.

`cubicIsLine` and `cubicAsQuad` are the other two, and both decide what a saved
file says: the first whether an imported `C` is stored with null handles and
re-emitted as `L`, the second whether the serialiser writes `Q`. Nineteen
survivors between them, including **`return false` turned to `return true` on
the guard that catches a curve doubling back**. Fifteen tests now, and the
quadratic ones are built forwards: elevate a chosen quadratic by the standard
formula and require the recovery to name the control it started from.

## The export could write XML no parser accepts

`exportSvg` closes whatever groups are still open when the shapes run out:

    for (let i = open.length - 1; i >= 0; i--) lines.push(`${pad}${pad.repeat(i)}</g>`)

Narrow `i >= 0` to `i > 0` and the outermost `</g>` is never written. Every test
in `test/groups.test.ts` stayed green.

**The reason is which shape comes last.** That loop runs only when the final
shape in paint order is inside a group. The existing "writes a group as one g"
test groups two of three shapes and leaves the third loose, so the close happens
on the way past it instead; the nested test does reach the loop but counts `<g`
and never counts `</g>`.

Three tests now: one group and one nested pair with the last shape inside, both
checked with a depth walk that requires the tags to balance and never to go
negative, and a round trip through `importSvg` because an unclosed `<g>` is a
file that will not reopen. All three go red on that one character.

## A guard that is unreachable, and a test that says so

`importSvg` returns early on `defs`, `clipPath`, `mask` and `symbol`. The
comment beside it already said deleting it "passes all 97 of this file's tests".
The sweep agreed, and so did deleting it here.

**It is unreachable rather than untested.** `walk` recurses only into `g`, `svg`
and `a`, so the children of those four are never visited at all. Five tests
were written, checked against the deletion, and **they could not fail** -- the
exact defect this project's rules warn about, produced while fixing one.

They are kept, with the comment rewritten to say which mechanism holds them up.
Made to fail on purpose by widening the recursion to those four tags **and**
removing the guard: five red. So they pin the outcome across both mechanisms,
and the guard stays as what saves whoever widens the recursion one day. What
they do not do is cover that line, and the old comment claimed they would.

## One I called a defect and then read

`svg.ts:397`, clearing a group's parent on import, survives `k.id === g.parent`
inverted. Reported here mid-sweep as a likely data-loss defect. It is an
equivalent mutant: `kept` always contains `g` itself, so `some(k => k.id !==
parent)` is true whenever `g.id !== g.parent`, which no importer can violate,
and both spellings therefore decline to clear. The branch only fires on a
dangling parent id, and the walk that builds `groups` cannot produce one.
