## Class 1. The pixel-fit lattice moved under the gesture drawing on it

**Severity: high. Every rectangle or ellipse drawn with pixel fit on and
something already selected.**

`phase()` read the selection fresh on every snap, which §25 defended as correct:
the lattice should follow what you are working on. It does. And a create drag
**replaces the selection with the shape it just made**.

Measured, drawing with an unstroked shape selected and a one-unit stroke pending:

```
phase before the press: 0     phase after the first move: 0.5
corners x = 40, 60.5, 60.5, 40
```

A rectangle 20.5 units wide: two edges painting on whole pixels and two not,
which is precisely the failure §25 exists to prevent. The drawn grid moved with
it, so the corner already committed at 40 sat on no gridline at all — §9's
contract, broken half a unit at a time.

**Fixed** by having a drawing tool ask the pending style rather than the
selection. That is the honest answer as well as the stable one: a tool that is
drawing is asking about a shape that does not exist yet, and the pending style is
the only description of it.

**A freeze-at-the-press went in first and came out again.** It followed the
transform box's principle of capturing at the press, it looked right, and then it
was measured: with the rule above in place, removing it changed nothing. Nothing
else moves the phase mid-gesture — a node drag does not alter the selection, and
shape and backdrop drags snap a displacement, which is phase-invariant. Shipping
a guard that cannot be shown to do anything is the habit this project keeps
catching itself in; see Class 6 for the third instance in two days.

The canvas no longer derives the phase at all. The controller owns it and hands
it over in `OverlayExtras`, so there is one source rather than two that agree.

## Class 2. Two owners for one disabled flag, and a trace that ran twice

**Severity: high.**

`traceBackdrop` set `#traceGo.disabled` directly; the store subscriber sets it on
every notification. Any unrelated update during the await re-enabled the button:

```
after click:  disabled = true
after any store notification: disabled = false
```

Clicking again ran a second trace — **4 shapes instead of 2**, two identical piles
exactly on top of each other, and one `Ctrl`+`Z` reaching only one of them. The
mirror case: removing the backdrop mid-flight left a lone enabled Trace button in
a group that was otherwise greyed out, because the `finally` overrode the
subscriber.

**Fixed** with a `tracing` flag that only `traceBackdrop` writes and only the
subscriber reads, so the two cannot disagree.

Related, same function: nothing re-checked the document across the awaits, so a
trace could commit into a live drag and be destroyed by the Escape that ended it.
Now re-read and refused.

## Class 3. Thirteen seconds of nothing

**Severity: high, and entirely a matter of honesty.**

A 900 by 900 photograph at the defaults: **13 117 ms of blocked main thread, 3
animation frames in 13.2 seconds**. The disabled state was set and never painted,
because the work started in the same task. On the small fixture the disable
window was never observed at all.

**Fixed** as far as it can be without a worker: the status line says `Tracing…`
and two frames are yielded before the work begins, so the freeze is announced
rather than mysterious. The freeze itself is now a stated limitation in the
manual. A worker would fix it properly and is not in scope here.

## Class 4. An exact comparison for a question about geometry

**Severity: medium.**

`rectSubpath` deduplicated a vanished side with `===`. When a side truly
vanishes the two coordinates *are* bit-identical, so it looked safe. A width one
ulp above twice the radius is not:

```
rectSubpath(0, 0, 2.1000000000000005, 20, 1.05)
→ M 1.05 0 H 1.05 C …      two H commands, a zero-length one among them
```

Which is the zero-length command the loop exists to prevent, and a path carrying
one can never be simplified again. The two other places in this codebase solving
the identical problem both use a tolerance — `roundCorner`'s `MEET` and
`fuseDegenerate`'s `DEGENERATE`. `rectSubpath` was the odd one out. **Fixed** by
giving it the same `MEET`.

## Class 5. Boundary snapping cost a frame per pointermove

**Severity: medium.**

The 1-D tier runs whenever no vertex is in reach, and `nearestOnPath` projected
every segment in the document. On a traced drawing of 2 400 segments, hovering
empty canvas cost **12.8 to 16.7 ms** — a dropped frame for doing nothing. It was
pure hit-testing until snapping started calling it on every move.

**Fixed** with a control-hull rejection before projecting: a cubic lies inside
the box of its four control points, so anything further than the reach cannot
win. Measured the same way before and after:

```
without the hull reject: 14.631 ms per call
with it:                  0.668 ms per call
```

## Class 6. Three claims that were measured wrong

The pattern of the day, and the most useful thing the review found.

- **"Consecutive points are 0.5 or 1.0 apart."** Stated in a comment, in
  ARCHITECTURE §26, and in a test, and offered as the measured fact justifying
  the removal of a guard. Two midpoints across a turn are **√2/2 ≈ 0.7071**
  apart, and on a checkerboard *every* gap is. The conclusion survives — 0.5 is
  the true floor and nothing is ever 0 — but an enumeration is a stronger claim
  than a bound, and this one had never been run against a diagonal. Both lanes
  found it independently.
- **"Auto-trace costs +5.6 kB raw, +2.0 kB gzipped, and the extra is the panel
  and the shape building."** It is not: that is the code alone. All in it is
  **+6.9 kB / +2.3 kB**, and the ratio against VTracer is 120×, not 139×.
- **"The right-angle pass is what makes a traced rectangle come back as a
  rectangle."** False for every rectangle one pixel wide or tall, which is
  exactly the 1-px-stroke case this editor is aimed at. The pass needs two
  straight lattice steps each side of a corner, so a single pixel traces to a
  diamond of half its area. Two pixels and up are exact. Now a stated limit.

## Class 7. A value computed, reported in three documents, and never shown

**Severity: medium.**

`circulariseSubpath` returns `fused`, the count of nodes welded because they
shared an angle. `rg '\.fused' src/` found the field's definition and nothing
else. `circulariseSelection` destructures three other fields and not that one, so
the status line never mentioned it — while the docstring, ARCHITECTURE §24 and
the shopping list all said the user was told. **Fixed** by telling them.

## Class 8. Controls offered in states where they can only refuse

**Severity: medium.** The Class 9 pattern from the morning, twice more.

- **Fit selection to pixels** was enabled on a mixed-width selection, where the
  readout two lines away already said `mixed widths` and the only possible answer
  was "no one lattice fits them all".
- **Shift+F, Delete, Shift+B, Shift+J and Shift+M all fired mid-drag.** The drag
  holds node indices into an array the operation splices; the edit folds silently
  into the drag's batch; Escape then rolls back both with no redo. Delete had this
  from the beginning and the four new shortcuts widened it. Now refused during a
  gesture, with Escape and Enter deliberately still allowed.

## Class 9. The readout named the node it was excluding

**Severity: medium.**

`snapPreview` passes no exclusions, which is right for a hover — a point that
does not exist yet may land on any node — and wrong the moment something is being
dragged, because the node under the pointer is the one the drag itself excludes.
It read `on a node` for the whole of every node drag, showing that node's own
coordinates. **Fixed** by not claiming a snap while a drag is live.

## Class 10. Dead code with a false explanation, again

`phaseOf` folded its result through `((x % 1) + 1) % 1` to avoid a negative zero,
with a comment explaining why. The guard above it already rules out every input
that could produce one, verified across nine widths. **Fixed**: the fold is gone,
and a finite check took its place — `Infinity % 1` is `NaN`, which broke the
stated `[0, 1)` contract and rendered as `offset NaN`.

## Class 11. A noise control that could not express its own example

`traceImage` floored `minPoints` at 3. A single stray pixel traces to a
four-point ring, so `minPoints` of 0, 1, 2, 3 and 4 all behaved identically and
the case `raster.ts` names as the reason the control exists needed 5. **Fixed**:
floored at 0, so the number means what it says.

## Class 12. Two smaller ones

- `fitToPixels` passed `true` for a refusal, so "Already on the pixel grid"

- `FuseRefusal`'s docstring promised a `null` the function never returns, and
  `fuseDegenerate`'s said it welds away *every* zero-length segment when it stops

## Tests that could not fail

The mutation lane ran **91 mutations against the sources and 17 against the
browser scenarios: 72 and 9 killed.** No wholly dead test of the kind the morning
found, which is progress. What survived is below, and all of it is now fixed.

| Test | Mutation that survived | Why |
|---|---|---|
| `rounds a square to its own limit as a circle` | dedup survivor takes `hOut` from the wrong node | Every assertion was anchor-only. The mutant emits four cusps and identical anchors |
| `welds across the seam without re-rooting it` | `keep = wraps ? second : first` → `first` | Fixture had no handles, so both spellings give the same points |
| the whole `fuseDegenerate` block | `DEGENERATE = 1e-7` → **`3`** | Pinned from below, unbounded above. A repair welding anything within three units passed everything |
| `lands the traced square where the pixels were` | `toDoc` transposes x and y | **Both placement fixtures were symmetric.** 10..30 in each axis, so a transposed mapping gives identical numbers |
| `leaves a phase of zero where the old grid put it` | any mutation of `snap` | `expect(snap(p, 2, 0)).toEqual(snap(p, 2))` — `phase` defaults to 0, so this is one call compared with itself |
| `finds the hole in a ring and names its parent` | six separate mutations of the parent search | One outline, so `parent` defaults to 0 and is right whatever the search decides |
| `drops a speck below the noise floor` | `<` → `<=` | Thresholds 8 and 3 against a 4-point ring never touch the boundary |
| `stops at two nodes` | the floor it guards → `<= 0` | `fuseNodes`' own check holds the line; the assertion was open-ended |
| `snapOrder` (browser) | `reach: REACH_PX * scale` → `REACH_PX` | **The scenario's own headline claim.** Sixteen times the true reach, and nothing was placed between the two distances |

**The lesson is one line: symmetric fixtures cannot detect asymmetric defects.** I
made that mistake in two separate files — `[raw, raw]` and a 10..30 square — while
explicitly hunting for it in a third. Every fixture involved is now asymmetric.

## Recorded rather than fixed

- **`pointInPoly` returning a constant `true`, and the innermost-box tie-break,
  survive every fixture I could construct.** The reason is structural: the scan
  is row-major, so a nested outline is always found *after* the one containing
  it, which makes "innermost" and "last qualifying" the same answer; and a hole
  is by construction inside the region whose outer boundary produced it. Reaching
  either needs an outline whose box is strictly inside another's while its
  geometry is not, with the wrong one innermost. Both are the reference
  implementation's, both are kept, and neither is claimed to be covered.
- **`projectToCubic`'s one-sided error scales with segment length** — 6.7e-6 of
  it, so 6.7e-2 on a 10 000-unit segment. Unchanged by these commits, but the new
  tier rule is what makes it matter: boundary now beats grid, so on a large
  document the more specific tier hands back the less exact coordinate. Left
  because fixing it means a better projector, which is its own piece of work.
